# Правила разработки проекта

## 1. Работа с существующим кодом
- Перед каждым заданием изучай связанные с ним файлы и их зависимости.
- Не переписывай целиком рабочие файлы без обоснованной необходимости.
- Сохраняй существующие функции, поведение элементов и совместимость со старым кодом.
- Не удаляй код, если не доказано, что он больше не нужен.
- Не создавай дубликаты существующих функций, стилей и компонентов.

## 2. Архитектура
- Разделяй проект на логические модули по их назначению.
- Не помещай всю реализацию интерфейса, бизнес-логику и данные в один файл.
- Выделяй самостоятельные системы в отдельные модули, когда это упрощает сопровождение.
- Не создавай отдельный файл для каждой мелкой функции или элемента.
- Перед созданием нового файла проверяй, нет ли уже подходящего модуля.
- Поддерживай понятные имена файлов и единый стиль организации проекта.
- Не меняй технологический стек без предварительного согласования.
- Учитывай текущую архитектуру. Не добавляй сборщик, фреймворк или сервер без необходимости.

## 3. Дизайн
- Используй папку Design и другие предоставленные материалы как источники требований к интерфейсу.
- Сопоставляй результат с референсами, а не придумывай дизайн вместо них.
- По возможности разделяй стили по страницам и компонентам.
- Не создавай хаотичные переопределения CSS и повторяющиеся правила.
- Не изменяй несвязанные элементы интерфейса без необходимости.

## 4. Безопасность изменений
- Перед крупными изменениями проверь состояние Git и наличие незакоммиченных пользовательских изменений.
- Не удаляй и не перезаписывай пользовательские изменения без разрешения.
- Вноси изменения небольшими, проверяемыми этапами.
- Не запускай опасные команды и не удаляй данные ради устранения обычных ошибок.

## 5. Проверка
- После каждого этапа проверяй изменённые файлы, импорты, подключения и зависимости.
- Запускай доступные проверки и тесты, подходящие для проекта.
- Если есть браузерные инструменты, проверяй интерфейс и интерактивность.
- Не утверждай, что тест пройден, если он фактически не запускался.
- Если проверка невозможна, явно укажи причину.

## 6. Отчёт
В конце каждой задачи указывай:
- Какие файлы созданы, изменены и удалены.
- Что конкретно реализовано.
- Какие проверки действительно выполнены.
- Какие ошибки остались.
- Как проверить результат вручную.

Не считай задачу выполненной только потому, что план составлен или код был сгенерирован. Задача завершена, когда изменения внесены и результат проверен в пределах доступных инструментов.
